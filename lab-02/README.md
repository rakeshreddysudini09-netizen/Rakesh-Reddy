## 1. Overview and Objectives
In this laboratory assignment, we develop a production-ready REST API integrated with an embedded relational database engine (**SQLite**):
1. Setting up a Node.js project with `express`, `sqlite`, `sqlite3`, and `nodemon`.
2. Initializing the SQLite database file (`books.db`) and creating a `books` table with auto-incrementing primary keys.
3. Seeding the database automatically with 10 sample books.
4. Structuring server startup with an asynchronous `initializeDBAndServer()` function using `async/await` so the Express server only accepts requests after the database is connected and ready.
5. Implementing complete **CRUD** (Create, Read, Update, Delete) operations using parameterized queries (`?` placeholders) to guard against SQL injection.
6. Enforcing input validation and HTTP status code semantics (`200 OK`, `201 Created`, `400 Bad Request`, `404 Not Found`, `500 Internal Server Error`).

## 2. Database Schema

The SQLite database stores books in the `books` table:

```sql
CREATE TABLE IF NOT EXISTS books (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  author TEXT NOT NULL,
  price INTEGER NOT NULL,
  pages INTEGER NOT NULL
);
```

### Table Column Details
| Column Name | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER` | `PRIMARY KEY AUTOINCREMENT` | Unique identifier generated by SQLite for each book |
| `title` | `TEXT` | `NOT NULL` | Title of the book |
| `author` | `TEXT` | `NOT NULL` | Author(s) of the book |
| `price` | `INTEGER` | `NOT NULL` | Price in INR |
| `pages` | `INTEGER` | `NOT NULL` | Total number of pages |

## 9. Security: Parameterized Queries Explained

### What is SQL Injection?
If we directly concatenated strings into our SQL queries:
```javascript
// DANGEROUS! Never do this!
const query = `SELECT * FROM books WHERE id = ${req.params.bookId};`;
```
An attacker could pass `1; DROP TABLE books;`, which would execute both commands and wipe out the database.

### The Solution: Parameterized Queries with `?` Placeholders
```javascript
// SECURE!
const query = `SELECT * FROM books WHERE id = ?;`;
const book = await db.get(query, [parsedId]);
```
The database engine treats the input inside `?` strictly as data/literal values, not executable SQL syntax. Even if a user enters malicious SQL keywords, they are escaped safely.

## 11. Viva Preparation Notes

1. **What is the purpose of `initializeDBAndServer()` using `async/await`?**
   - Connecting to a database is an asynchronous I/O operation. If the Express server started listening before the database connection was established, incoming requests would fail because `db` would still be `null`. Wrapping the DB connection and `app.listen()` inside an `async` function with `await` guarantees the database is ready first.

2. **What is the difference between `db.get()`, `db.all()`, and `db.run()`?**
   - `db.all()`: Executes a `SELECT` query and returns an array of all matching rows.
   - `db.get()`: Executes a `SELECT` query and returns only the first matching row as an object.
   - `db.run()`: Executes an action query (`INSERT`, `UPDATE`, `DELETE`, `CREATE TABLE`) and returns execution metadata like `lastID` and `changes`.

3. **Why do we use HTTP status code `201` for POST?**
   - HTTP `200 OK` indicates standard success, whereas `201 Created` specifically indicates that the request succeeded and led to the creation of a new resource on the server.
